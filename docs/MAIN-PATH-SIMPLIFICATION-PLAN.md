# 主路径精简计划

本轮只处理已批准的日常使用问题：环境准备反复交给 Worker、运行故障被当成业务 Replan、
继续入口与状态提示重复、最终报告缺少功能影响说明。机器事项为 `DAILY-01`；完成状态见
[CURRENT.md](CURRENT.md)。本文件描述范围，不代表已通过验收或已经发布。

## 保留、合并和删除

| 范围 | 实施决定 |
|---|---|
| 执行主线 | 保留同一 ChangeRun、单 Writer、Candidate 和 Core 门禁，不增加 Runtime |
| 环境准备 | 可选 `verification.prepare_commands` 编入批准合同，首次 Worker 前由控制器执行 |
| 普通实现问题 | 验证失败和 Reviewer finding 走原 Repair；改变目标或授权边界才修订合同 |
| 运行问题 | 明确 Reviewer timeout 沿原门禁链重试一次；可信证据重算沿原 Observation/Decision 路由 |
| 继续入口 | 保留 `change`；删除重复的公开 `run`、`retry` 和无调用 CLI 包装 |
| 状态提示 | `change`、`status`、`explain` 复用同一安全动作投影，删除 Agent `next_steps` |
| 最终报告 | 采用同次 Reviewer 可选的功能影响与代码位置，不增加总结模型 |
| 兼容 | 新 Run 使用执行协议 2；旧 Run 可查看、停止、可信交接，不能原地自动执行 |

备选是保留所有旧命令并增加修复提示；它不能减少重复职责，本轮不采用。内部仍被调用的
Core 验证恢复、Artifact 读取和 Task Card 恢复保留，不为压行数删除必要边界。

## 环境、恢复和授权

- 准备命令必须来自固定源版本的项目配置，并逐字进入批准合同。空配置保持原行为。
  非空准备命令需要人工批准，不能借 bounded 模式批准任意安装脚本。
- 同一批准摘要最多准备一次，开始执行前持久化预算。失败或进程终态未知时保留现场；
  不从错误信息猜安装命令，不自动重放未知写入。准备成功不代表验证通过。
- 准备期间允许响应停止，不能长时间持有状态锁。准备只能改变允许的环境内容；源码、
  未忽略文件、HEAD 或 Git 控制面变化必须停止。
  停止需绑定已启动的执行进程；命令间无活动进程时明确拒绝，不能报告已停止整个阶段。
  准备终态未知时没有自动恢复出口，活动绑定未解除前也不能生成可续跑的交接。
- Reviewer timeout 恢复继续遵守原 Candidate、策略、风险、进程与预算检查。
- Core 证据重算只接受当前合同、同一 Candidate、可解释 Workspace 和已结束的执行。
  原始失败记录保留，重算追加新的判断；没有可信测试或独立审查时不能产生成功。
  需要累计审查却缺少相应结果时继续交还人工。
- Worker 写入中断、未知外部副作用和授权变化不是自动恢复场景。

## 展示与交接

Reviewer 的功能影响属于审查意见。引用位置必须匹配冻结 Candidate；无效位置隐藏，
不编造行号、不改变门禁。缺少可选摘要时展示现有 Git 变更与验证事实。

旧 Run 的报告、Trace 和失败数据不删除。换机器仍通过任务分支、Task Card、合同和计划
创建新 Run，并重新核对现场；Provider 会话不作为可迁移的成功证据。

## 必要验收

1. 准备成功、准备失败、停止、未知终态与重启后禁止重复；批准页必须显示准备命令。
2. 实现失败仍可 Repair，证据不可信不能误走 Replan 或完成；重算不可重复、不可越界。
3. 同一 Run 的三种展示给出一致动作；旧命令退出，旧任务无法意外恢复 Writer。
4. 功能摘要无效路径或行号不进入可信代码导航，旧 Reviewer 输出仍可读取。
5. Codex、Claude 各一个受控日常任务，至少一次 Reviewer 打回后继续；真实运行和故障注入
   分开记录。Echo 既有任务只读核对，不修改业务仓库。
6. 最小充分回归、静态与仓库门禁，之后由 PR CI 覆盖跨平台；不机械本地重跑全量。

使用一个实现分支和一个 PR；本轮不自动合并、发布或增加 Provider、命令、状态、通用恢复系统。
若现有证据模型无法以小改动安全支持某项，先说明具体冲突，不用额外协议掩盖问题。
