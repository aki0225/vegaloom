# 计划与状态规则

- `vega-agent-evolution.json` 保存事项、依赖、验收条件和要求检查，不写“等待 CI”、
  “准备合并”等瞬时状态。已有状态事件的事项定义保持不变；尚无事件的未来事项可以随实现
  证据调整、重排或删除，但必须继续满足依赖校验并重新生成当前视图。
- `events/` 保存已经随实现进入 Git 的状态事件。实施机器计划事项的 PR 必须在同一个 Diff
  中增加对应事件；没有对应事项的普通修复、文档或维护任务不新增占位事件。事件进入 `main`
  后，状态才成为主线事实。
- 实施顺序固定为“增加事件 → 生成 `../docs/CURRENT.md` → 运行计划状态检查 → 交给 PR CI”。
  CI 失败或 PR 关闭时，事件不会进入主线；合并后不再补“状态已完成”的文档提交。
- 已进入基线的事件只允许追加，不得修改、删除或用后续事件掩盖。需要重新处理已完成事项时，
  追加 `reopened` 事件。
- 事项 ID、依赖和完成证据由 `../scripts/plan_state.py` 校验；`../docs/CURRENT.md` 由该脚本生成，
  不手工编辑。
- 计划修订必须保留已有状态事件事项的 ID、定义和历史含义。新增范围使用新事项，不把失败、
  阻塞或已完成事项改写成另一项工作。
