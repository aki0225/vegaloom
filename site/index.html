One writes, one reviews.

“我已经改好了，测试也过了。”

AI 这么说，
你真敢直接合进主线吗？

我们也不敢。

所以我们写了 Vega。

Worker 写完后，Reviewer 从一个全新的会话开始，只看任务、真实 Diff、 测试结果和项目规则，不接着 Worker 的对话往下说。

项目自己的测试必须真的跑通；改了什么、风险在哪里，也得说清楚。 证据不足，Vega 就停下来，保留现场，交给你接管。

Vega 不替你合并代码。它先把该看的证据摆在桌面上。

01 / 真实问题

同一个 Bug，两种交付方式

差别不在于“用了几个 Agent”，而在于最后留下了什么，失败时又会不会硬着头皮往下跑。

只听模型汇报

一句“改好了”，后面全靠人追

  1. 01模型修改代码，并口头说明已经完成。
  2. 02测试跑没跑、跑的是不是当前 Diff，需要重新确认。
  3. 03几百行 Diff 摊在面前，风险位置没有单独指出。
  4. 04进程超时或中断后，现场是否可信并不清楚。

经过 Vega

每一步都留下下一步能核对的东西

  1. 01先固定工作区和允许范围，旧改动不会混进本轮。
  2. 02Worker 的真实 Diff 经过范围、污染与风险检查。
  3. 03项目自己的验证命令实际运行，并记录结果。
  4. 04Reviewer 从新会话读取证据，Finish 再给出明确结论。
ready_to_commit 证据完整，等你检查 request_changes 找到问题，继续修改 needs_human 证据不足，停下来

02 / 六个检查点

从“开始改”到“能不能交付”

六个检查点只回答六个具体问题。任何一项缺证据，都不会被一句 approve 覆盖。

  1. 01

    Baseline

    先固定现场

    哪些改动属于这次任务？

    留下
    HEAD、工作区指纹、项目策略
    失败时
    基线不完整，任务不启动
  2. 02

    Worker

    看真实修改

    代码到底动了什么？

    留下
    执行状态、真实 Diff、退出结果
    失败时
    保留候选，不伪造完成
  3. 03

    Gates

    检查范围与风险

    有没有越界、污染或碰到高风险代码？

    留下
    Workspace、Scope、Risk 结果
    失败时
    停止验证和后续审查
  4. 04

    Verify

    跑项目自己的验证

    哪些命令真的通过了？

    留下
    命令、退出码、验证摘要
    失败时
    Reviewer 不能把错误说成成功
  5. 05

    Review

    换一个会话看证据

    Reviewer 找到了什么？

    读取
    任务、Diff、测试、规则与风险
    不读取
    Worker 的完整历史对话
  6. 06

    Finish

    把结论说清楚

    可以检查后提交，还是必须人工处理？

    核对
    完整性、新鲜度与最终状态
    输出
    证据事实、意见、上限和下一步

04 / 三种结局

停止，也是一种可信结果

Vega 不把所有运行都挤成绿色。结论必须和当时真正拥有的证据相符。

05 / Design Boundary

Vega 刻意不做什么

  • 不替代编码工具。它是外围 Harness，不是新的通用 Agent 框架。
  • 不宣传系统级隔离。新 Reviewer 会话不等于容器或操作系统安全沙箱。
  • 不自动提交。Vega 不执行 commit、push 或 release。
  • 不让意见盖过失败。approve 不能覆盖验证失败。
  • 不替人确认高风险。支付、数据库、并发等修改仍要人工检查。
  • 不从案例推导成功率。公开运行只说明对应现场发生了什么。

06 / Quick Start

先在一个边界明确的小任务上试

当前主会话修改代码，Vega 固定现场、跑验证、启动独立 Reviewer，再生成 Finish 结论。

如果你还不知道 Bug 在哪里，先由主会话调查并确认计划，不要让 vega do 猜范围。

PowerShell 
python -m pip install -e ".[dev]"
vega config check --repo .
vega loop bug --repo . --text "修复一个边界明确的缺陷" --mode assist
vega loop continue --repo . --run <run_id>
vega finish --run <run_id>
